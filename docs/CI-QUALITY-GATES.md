# CI Quality Gates, Test Lanes & Capability Matrix Specification

This document details the CI testing strategy, pipeline tiering, quality gate release blockers, and published capability matrix for the GTK Office Suite (**Letters**, **Tables**, **Decks**).

---

## 1. Test Lanes & Pipeline Tiering

To maintain rapid developer feedback without compromising test coverage or data safety, CI is partitioned into three distinct execution lanes:

| Lane | Trigger | Scope & Targets | Target Budget | Release Blocking? |
|---|---|---|---|---|
| **Fast Lane** (`ci.yml`) | Every `push` & `pull_request` | `cargo check`, `cargo clippy`, `cargo nextest` (unit/property/headless controller tests), `interop/validate_corpus.py`, doc tests, Flatpak container build | **< 3 minutes** (warm cache) | **Yes** |
| **GUI Lane** (`gui-tests.yml`) | PRs to `main`, `push` to `main`, scheduled daily | AT-SPI smoke tests filtered by affected app paths (`letters`, `tables`, `decks`), buffer-bridge roundtrip tests under `Xvfb`, visual golden matrix comparisons | **< 8 minutes** | **Yes** |
| **Nightly / Release Lane** (`nightly.yml`) | Scheduled daily, `workflow_dispatch` | Full LibreOffice interop oracle & parity corpus, bounded importer fuzzing (`cargo fuzz`), `cargo llvm-cov` code coverage, Flatpak installation and launch verification | **< 25 minutes** | **Yes** (conformance/loss-budget regressions) |

---

## 2. Published Artifacts & Capability Matrix

1. **JUnit Test Results (`junit-results`)**:
   - Published as an artifact by `ci.yml` via `cargo nextest` (profile `ci`).
   - Retained for **14 days** so test-level failure details survive job log retention.
2. **Capability Matrix / Conformance Scorecard (`conformance-scorecard`)**:
   - Generated by `conformance/scorecard.py` during nightly runs.
   - Retained for **90 days** as a published artifact tracking feature capability and format interop status across releases.
3. **Visual Golden Artifacts (`visual-artifacts`)**:
   - Retained on GUI visual regression failures containing baseline PNG, actual rendered PNG, and red-highlight pixel diff heatmap.

---

## 3. Release Blocking Criteria

The following regressions constitute hard release blockers:
- **Data Safety Violations**: Any loss of uninterpreted OOXML/ODF ZIP package parts promised as pass-through.
- **Tier 1 Journey Failures**: Any regression in fundamental create, edit, open, or save workflows across Letters, Tables, or Decks.
- **Loss Budget Exceedance**: Any unexpected loss-budget warning or format mismatch during interop validation.
